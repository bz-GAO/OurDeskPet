# 2026-10-20：标题、界面与平台入口

> 历史记录：本文件说明该轮实现和当时的后续判断，不再作为当前待办。当前状态与优先级见 [STATUS.md](STATUS.md)。

实施顺序：混合标题 → 设置与扩展主题/边距 → API 获取入口 → 瞬移独立预览。

## 本轮功能

- 首轮完整且非空的助手回复后，异步请求一次模型标题。本地标题先显示并保存；失败保留本地标题，不自动重试。手动改名优先，切换新会话后旧结果失效。已导入/恢复的历史不自动补发请求。调用沿用当前 API 配置，使用有限文本，不附带图片、附件全文、工具或搜索参数；请求用量记录到现有账本。
- 设置分类“人物与美术”简化为“美术”。滚动区给圆角及焦点留白；扩展页主要按钮、表单和 Tomo 面板采用同一主题令牌。系统原生下拉菜单的弹出层可能仍由 Windows/WebView 着色。
- 无可识别账户时以“获取 API”代替余额空行；读取失败仍显示错误/重试，不能假装用户未配置。已有 API 但缺账务授权时仍使用既有连接入口。
- API 配置下新增 Chat / Tomo 分组标题和 DeepSeek 获取入口；本轮是入口整理，现有表单仍保存 Desk Chat 配置，Tomo 独立配置需通过其控制协议管理。账户和扩展配置统一是后续任务，不能声称已共用密钥。
- Yaki 设置提供百炼获取入口。链接参考官方 API Key 文档；网页登录并不自动填入本机密钥。

## 瞬移审稿与实装

用户已确认先实装当前扫描线加少量粒子的方案。独立预览仍保留；正式应用采用轻量 CSS 扫描线及 30 个光点，不复制游戏素材。打开 Chat / 设置时先只读预判是否需要避让，无需移动则不播放动画；需要移动时先消散，在透明阶段移动，再重建。屏幕边缘校正复用同一控制器。

状态顺序：待机 → 600ms 消散 → 100ms 空档及原生移动 → 600ms 重建 → 待机。移动失败恢复可见；待执行请求只保留最新一项；拖拽、换装、隐藏及关闭中断动画；减少动态效果模式直接移动。原生调用发出前重新检查取消状态。粒子不扩大既有点击区域。

验证：前端构建与单元测试通过；浏览器验证正常移动时序、失败恢复、主动取消、拖拽/换装中断、最新请求合并及减少动态效果模式。原生定位算法测试覆盖多屏负坐标及缩放。实际双屏不同 DPI 和长时间连续交互仍需使用观察。

后续美术目标：增加更接近用户所述游戏角色风格的粒子消散、像素碎片及投影重建，但保持原创素材、轻量渲染和可中断行为；另行预览审稿，不在本轮提高视觉强度。

## 最小化恢复修正与粒子审稿

- 位置校正现在忽略最小化/隐藏窗口，不将 Windows 最小化期间的屏外坐标视为目标。
- 点击桌宠最小化按钮时先隐藏人物并等待绘制，再最小化；恢复后保持隐藏完成工作区校正，只播放显现段，避免再次消散。
- 新增恢复状态监听（尺寸、焦点、可见性及低频兜底查询），防止重复播放；最小化或定位失败会恢复人物可见。其他窗口与用户数据不变。
- Windows 下仅为主桌宠 HWND 设置 `DWMWA_TRANSITIONS_FORCEDISABLED`，关闭任务栏滑动还原过渡，不更改系统全局动画设置。依据：[Microsoft DWM 窗口属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。
- 浏览器模拟回归覆盖：先隐藏再最小化、忽略最小化坐标、隐藏定位、仅显现一次、原生调用失败及减少动态效果。Windows 实际任务栏观感仍以用户验收为准。
- 量子碎片候选版已设为默认：固定蓝紫/青色、不采人物 RGB，混合大小实心/空心碎片，去除模糊光晕和拖尾；旧扫描线渲染器继续保留在代码中，暂不提供用户切换入口。

## 边缘归位与拖动

- 边缘判断按底部居中的 180×162 可见人物区域计算，而不是按 280×410 的透明原生窗口计算；透明留白越过屏幕边缘不再触发瞬移。
- 对 3 个物理像素以内的 DPI 取整或松手越界，直接静默校正；只有实际可见人物明显越界才播放量子归位。恢复定位复用同一套几何规则。
- 拖动特效采用独立的手动交互路径：拖起时短促像素解离，移动中只保留稀疏边缘碎片，放下时聚合，不让人物在拖动时消失。
- 当前透明窗口无法把轨迹留在已经离开的桌面区域；第一版限制在窗口内做拖起/落下反馈。若以后确需长轨迹，再评估独立、鼠标穿透的特效窗口，避免扩大点击热区。
- 像素美术套组列入后续审稿：先核对 A.L.A.N / Cheer Mode 官方影像，再制作原创像素化提案；不直接复制影视帧或现成素材。
