## A. 先修复与小范围试版

1. 上轮收尾：核对安装文件与构建哈希、启动定位加固是否进入实际程序。已核对通过。
2. Tavily：密钥占位只显示“已保存”；移除面向普通用户的服务地址输入。没有自定义需求时使用内置官方地址，有密钥即可按搜索开关/路由使用；已有高级地址配置不能因隐藏输入而被误覆盖。
3. 阿里云：先区分授权文件丢失、进程间资料目录不同、模型账户指纹变化、解密失败和接口授权失败。只输出诊断状态，不输出密钥。恢复须验证原账户匹配，不把一个账户的授权自动绑定到其他账户。
4. 用量卡片：已修正余额/花费列对齐。设置页已统一为粉色系分区、普通文档流折叠和紧凑单行设置；复杂内容展开后自然推开后续分区，不使用吸顶覆盖。
5. 对话类型标签：普通对话试橙色、项目助手试红色底块；保留文字，不只依赖颜色区分。

## B. 近期实现：默认保存与输出位置

本节首版已实现，回归覆盖同文件连续写入、列表恢复、改名、保存开关、退出确认及保留 JSON 的移除操作。完整 GUI/异常退出仍需实机验收。

### Chat 自动保存

- 顶部保存按钮已替换成“自动保存 / 不保存”二态，默认开启；首次升级只发现受管理的会话文件，不扫描其他旧目录。保存文本、解析后的附件内容和图片元信息，不保存图片二进制。
- 默认资料目录采用运行时定位到的 Desk 项目根下 `Conversations`；设置 → Chat 可以修改位置。侧边栏文件夹按钮打开当前解析结果。自选旧目录保留原状，不迁移、不删除；路径不写死盘符。
- 稳定会话 ID 作为文件身份，显示标题可改但不能成为任意路径；每轮结束和改名后防抖覆盖同一 JSON，停止生成时保存明确的未完成状态。不按 token 逐次写盘。2026-10-20 经用户确认，首轮完整回复后追加一次异步模型标题请求，本地标题作为即时显示与失败兜底，手动改名优先。
- 原子写入、保存失败可见、权限撤销/目录断开时不误报成功；模式切换与同时保存不串会话。关闭应用时有界等待，不能只依赖页面卸载事件。
- 重启恢复列表；“移除关联”和“删除本地文件”明确区分，删除须独立确认。保留现有 JSON 导入兼容，损坏文件隔离而非覆盖。
- 自选目录只授予该目录下受约束会话文件的权限，不能扩大助手源码或任意文件访问权限；图片数据/原始附件是否落盘另行决定，先延续当前导出范围。
- 验收：连续两轮只更新同一文件；关闭保存后不落盘；重启恢复；切目录不移动/删除旧记录；冲突、只读目录、断盘、异常退出不破坏原 JSON。

### Yaki 默认 output

- 新项目默认进入 Yaki 的 `output` 目录，设置可修改；与 Desk 共用 Yaki 自己提供的默认目录，不由 Desk 另存一份。
- 已统一放到用户可写的数据根下的 `RinaYaki/output`，遵循 Yaki 的配置根覆盖项；源码启动也不再单独选项目根目录，不与编译缓存混在一起。
- 旧任务继续引用原目录，不自动搬动视频；新任务检查实际可写性、目录链接和项目名冲突。只自动建立默认 output，自定义的不存在目录不会被创建。长视频空间预估仍属后续优化。
- 原生和 Desk 设置读取同一来源，默认目录修改只影响新任务；改为空恢复默认 output。

## C. 美术与自定义：人物首版已实现，热区后续

- 配色令牌已统一到 `app/src/rinaTheme.css`，设置分区采用纸白灰，粉色边界内使用灰色选中态；详见 [视觉规范](DESIGN-SYSTEM.md)。不把粉色宣称为璃奈官方应援色。
- 普通 Chat/助手标签先试宫下爱橙与优木雪菜红；颜色仅用于类型标签，错误状态保留独立语义。
- 已新增虚线“＋”入口及四个人物槽位，支持名称、预览、保存、更换图片和启用。自定义方案可快速重命名并经独立确认删除；三个内置方案固定，不提供复制入口。自定义资源存用户数据目录，不覆盖内置包；图片校验格式、尺寸和字节上限，不执行 SVG/脚本。
- 美术页已拆为“人物 / 主题”两个纵向分块，主题首版提供纸白灰与粉色并跨窗口持久化；粉色主题使用同色系深浅层级。璃奈板、通知板与交互热区不随主题或人物方案替换。
- 本版仅替换人物图，璃奈板、通知板和交互热区固定，不开放替换。四个人物槽位完整后才保存；切换设置分类保留草稿，放弃草稿使用独立确认弹窗。
- 第二阶段再做热区编辑：拖拽位置和大小、归一化坐标、缩放/DPI 预览、重叠与边界检测、还原默认、键盘调整。视觉图片与点击区域分层存储，不直接改源码。
- 编辑热区时不触发真实按钮动作；关闭和恢复入口始终可达。确认图片版权与分发许可后再进入公共安装包。

## D. 安装包与发布（设计，不在本轮制作安装器）

- Desk 为主安装器，Yaki/Tomo 为可选组件；展示勾选项、空间/下载量、目标路径，不默认下载模型或开机启动。
- 默认 `<用户选择目录>/OurDeskPet/{RinaDesk,RinaYaki,RinaTomo}`；区分程序目录与可写用户数据。若用户已经选了 OurDeskPet，避免重复嵌套。
- 用户安装预编译 Desk，不需要 Rust、Cargo、Node 或现场编译。开发端/CI 负责构建；命令行源码启动仍需要开发依赖，不应被包装成用户级免安装方案。
- Yaki/Tomo 需单独验证 Python 运行时、FFmpeg、WebView2、NapCat 等依赖能否合法重分发；模型按需下载且可指定目录。三仓库保持独立开发，不强制单独提供面向最终用户的安装器。
- 发布清单锁定三组件版本、协议与 SHA-256；通过 GitHub Releases 分发，安装器先验签/校验再安装。断网、取消、部分组件失败、卸载保留数据要有验收；不执行仓库 README 或任意在线脚本。
- 自动更新/回退晚于首次安装闭环；开发阶段继续使用经验证 Git 检查点。先做干净 Windows 虚拟机安装测试，再宣称开箱即用。
