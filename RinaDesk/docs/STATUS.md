# RinaDesk 当前状态与后续开发

更新日期：2026-10-26。

本文件是 RinaDesk 当前完成度、未完成事项和开发优先级的唯一入口。功能细节以对应专题文档为准；带日期的路线图和迭代文件仅记录当时的决策，不再提供当前待办。

## 当前基线

- 自动移动相关运行时代码、步态资源、测试、实验页和后续计划已经移除。屏幕边缘归位、打开面板时避让、手动拖动及其粒子反馈继续保留。
- 当前源码基线包含事件音效、语音结合回答、普通对话→项目助手确认跳转，以及 Tomo 通知/深夜休眠控制。2026-10-26 复查后，前端单元与 Playwright UI 套件、TypeScript/Vite 生产构建、Rust 161 项（另 3 项付费/联网测试忽略）全部通过。
- Chat 已具备本地受管理会话、自动保存开关、稳定文件身份、异步模型标题、本地标题兜底、手动重命名优先、上下文压缩、搜索、项目助手和确认式模式跳转。
- 设置已覆盖 API 方案、账户/本机用量、Chat 参数、项目助手权限、美术方案、主题、事件音效、开机启动和运行诊断。
- RinaYaki 使用注册目录与版本化桥接；RinaTomo 使用本机回环控制协议。三个项目仍独立保存配置和凭据。
- A.L.A.N 像素方案保留待机、休眠、说话面罩闪烁、拖动无人机和手动拖动粒子，不包含自主移动行为。拖动时原生绘制区临时使用完整 420×230 下部画布，释放 360 ms 后恢复紧热区，优先避免无人机与阴影被裁切。

## 后续建议（待用户审核，不是已批准排期）

### 收尾：文档与构建基线

1. 保持本文件与专题文档同步，已完成事项不再留在“后续”清单中。
2. 每次语音/原生窗口批次完成后使用 `scripts/Build-Local.ps1` 替换本机安装副本并做启动冒烟；源码测试通过不等同于安装副本已更新。
3. 在明确要求推送前只建立本地 Git 检查点。未来推送前检查历史中的审稿大图；是否另行整理发布分支由用户决定，不自动改写已有历史。

### 进行中：Desk 安装器开发预览

当前草案见 [INSTALLER-DESIGN.md](INSTALLER-DESIGN.md)：安装器不配置 API，也不在用户电脑编译。2026-10-25 已将当前 Desk 重新打包到工作区顶层预览，接入简洁语言选择、勾选式协议占位、首次安装、同版本修复、旧版本更新、禁止降级和不完整安装修复；安装时隐藏文件级百分比和详情页，成功后直接进入完成页。欢迎页与完成页已经接入用户确认的墨绿像素璃奈竖幅；八个交互页面通过脚本真实安装／卸载并保存截图，见 [安装器预览](installer-preview/README.md)。

1. 方案目标是交付预编译 RinaDesk，最终用户不安装 Rust、Cargo 或 Node；这不是已交付安装器的声明。
2. 在干净 Windows 环境验证 WebView2、首次启动、项目定位、用户数据目录、升级保留数据、取消安装和卸载保留策略。
3. RinaDesk 固定安装；Yaki/Tomo 只在版本化发行物、依赖许可、体积和 SHA-256 齐全时作为默认不选的可选组件出现。没有可发布组件时跳过选择页。
4. 模型、语音资源和大型运行时由所属组件按功能首次使用下载，不随 Desk 默认安装，也不归 Desk 卸载器删除。

### 候选：附件基础设施与 PDF 文本层

1. 先实现可取消解析任务、来源块、覆盖范围和警告，再增加新格式。
2. PDF 第一阶段只做本地文本层、页码和扫描页提示；不同时引入 OCR、Python 模型运行时或云端视觉。
3. 会话文件工具只读取当前 Chat 已附加的资源，不继承项目助手的源码权限。

### 候选：扩展与 API 状态统一

1. Desk 可统一展示 Chat、Yaki、Tomo 的连接状态、配置归属和官方入口。
2. 不建立跨项目明文密钥库；三个项目继续拥有自己的配置和凭据，桥接只返回是否已配置及非秘密状态。
3. 平台跳转只打开官方页面，不代表授权完成，也不自动填入本机配置。

### 长期：自定义人物热区编辑

具体排期后续讨论；设计需覆盖归一化坐标、DPI/缩放预览、重叠与边界检查、键盘调整和还原默认。图片与点击区域继续分层存储，编辑状态不得触发真实按钮。

## 明确延期或终止

- 自动移动：已从项目和计划移除，不保留隐藏开关或运行时脚手架。
- 自动更新、跨组件统一安装器：晚于 Desk 单体安装闭环。
- OCR、Docling、云端视觉：晚于 PDF 文本层和真实使用反馈。
- 助手直接执行 UI 动作：仅保留研究边界，必须先有封闭动作集合、权限和逐次确认设计。
- 自动抓价、自动改计费规则和大型统计平台：不在当前范围。
