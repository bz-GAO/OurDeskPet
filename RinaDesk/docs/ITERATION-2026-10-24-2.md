## 一、闸 2 对齐：create 请求补全（agent.log 驱动）

首验暴露两个错误：`不支持的语言设置`、`请填写保存位置和项目名称`——
agent 的 create 请求没对齐 Yaki 桥的完整契约。修复：

- **闸 2 弹窗改迷你表单**：项目名称 + 保存位置，可编辑、有默认值。
  默认值即 Yaki 维护的"默认项"：保存位置取桥 settings action 的
  `defaultProjectDir`（闸 1 顺带免费拉取，`\\?\` verbatim 前缀入库前剥离，
  参照 useConversationStorage/displayConfigPath 先例）；项目名由标题推导
  （`suggested_project_name`：过滤 Windows/桥不接受字符、折叠下划线、
  限长 60、空标题回退固定名）。
- create 请求最终形状：`video{kind,source,title,acquisition{session,
  quality:"auto"}} + sourceLanguage=ja + targetLanguage=zh-Hans +
  name + parent`，与扩展页一致。
- 闸 2 失败时提案自动放回"待开始"，改完表单可直接重试。
- 同期并行改进（保留）：agent.log 轮转（1MB）、gate1 `previewing`
  防重入、提案池满时只逐出未激活提案并报错。

## 二、⚠️ 交接重点：release 链接吞字面量悬案（待接手）

工具链第二次出现"字符串消失"：

- **现象**：`json!({"suggestedName":…,"defaultParent":…})` 的两个键字面量
  在 release exe 中**字节级不存在**，同函数体其他字符串（日志文案、
  指针路径）全部健在；debug 构建与 `cargo test`（debug+release）均正常，
  仅 release exe 缺。第一次是调用 `extension_tools::extension_status` 致
  测试二进制 STATUS_ENTRYPOINT_NOT_FOUND（改走 `diagnostic()` 规避）。
- **当前绕开**：键改运行时拼接（`"suggested".to_string()+"Name"`），
  机制上不依赖字面量存活；cargo 153 全绿。
- **注意**：字节搜索探针自此失效（前端字符串本就压缩嵌入搜不到是正常的）；
  悬案的实际影响只能真机验证——闸 2 表单若预填正常即可视为无运行时危害。
- **自查线索**：①字节搜索法可能本身不可靠（LLVM 字符串合并/去重）；
  ②对比 debug/release 的 `dumpbin`、查 LTO/增量设置、`cargo clean` 全量
  重建复现、最小 json! 用例二分；③构建缓存已迁
  项目内 `.build-cache/cargo-target`（非 LOCALAPPDATA）。

## 三、任务卡体验两轮打磨

**四连改**（第一轮反馈）：

- 进度条：`agent_task_status` 透传 `stage/completed/total`，卡片内复刻
  扩展页阶段模型（六阶段中文标签；download/translation/refinement 可测

**五连改**（第二轮反馈）：

  （Rust `get_webview_window` + `emit_to("settings")` 定向投递；新建窗口
  时 created 后延迟 600ms 再投递防监听未就绪）。

- 卡片重排：标题去时长；标题下封面预览（thumbnail 随闸 1 入库/入卡）+
  右侧两行"时长/画质"（画质取 acquisition.quality）；estimate 在导出
  阶段及之后隐藏；「一键导出」去"默认样式"文案、绝对定位右下与角标
