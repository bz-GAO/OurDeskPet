# Windows 安装包方案（开发草案）

更新至 2026-10-25。工作区顶层 `RinaDesk-preview-x64-setup.exe` 已重新打入当前 Desk 源码，并加入简中／英文选择、开发协议占位、同版本修复、旧版本更新、禁止降级和不完整安装修复。它仍是未签名开发预览，不是可发布版本。构建缓存固定复用项目内 `.build-cache`；唯一 Setup.exe 与 SHA-256 覆盖到 RinaDesk、RinaYaki、RinaTomo 文件夹旁，不堆积重复包。

## 产品范围与实现路线

- 第一版只交付 Windows x64 Desk，Tauri + NSIS 生成 Setup.exe，默认当前用户安装。Yaki/Tomo 继续作为独立组件接入，不在 Desk 安装过程中安装 Python、下载模型或登录 QQ。
- 编译只在开发机／发布构建环境执行。用户电脑接收预编译程序，不安装 Rust、Cargo、Node 或编译缓存。
- 优先使用 NSIS 原生页面、目录选择和进度控件，少量调整版式与文案；不另做依赖 WebView2 的 React 安装器，避免安装器本身依赖尚未安装的运行环境。
- 需要首页合并目录栏时再维护受控 NSIS 模板，锁定工具版本并跟进上游安装／升级修复。第一版不做特殊形状窗口、复杂皮肤、自动更新或跨组件统一安装器。
- NSIS 安装器和卸载器显式使用 Desk 当前的 `app/src-tauri/icons/icon.ico`，与程序图标保持同源；不另画安装器专用标志。作者信息只放完成页的低强调位置，不做贯穿所有页面的水印。

## 窗口与必要文字

常规小矩形，初稿按约 520 × 360 逻辑像素规划，实际以原生控件及 DPI 测试为准；不是硬编码物理像素。布局只有当前状态所需内容。

| 页面 | 显示内容 | 操作 |
| --- | --- | --- |
| 语言 | 简体中文、English | 选择安装界面语言；不影响 Desk 内语言 |
| 协议 | 当前协议正文 | 必须接受才可继续；开发预览使用明确的占位文本 |
| 安装前 | 图标、RinaDesk／版本、安装地址栏 | 地址可编辑；右侧“浏览…”；“安装”“取消” |
| 执行中 | 当前阶段、一条进度条、适用时的百分比与下载量 | 可安全取消时显示“取消”；日志收在“详细信息” |
| 完成 | “安装完成” | “启动 RinaDesk”“完成” |
| 失败 | 简短原因 | “重试”“关闭”；可展开脱敏详情 |

2026-10-25 的双语预览使用受控生成后补丁：每次由 Tauri 生成当前 NSIS 脚本，脚本按固定标记加入语言页、安装状态文案和完成页默认值；上游模板变化时构建直接失败。欢迎页与完成页已经换成用户确认的墨绿像素璃奈竖幅；项目保留无损 PNG 源图，并由固定的 164 × 314、24 位 BMP 进入 NSIS。八张真实页面截图见 [安装器预览索引](installer-preview/README.md)。截图由 Windows UI Automation 与原生窗口 API 生成，不依赖 CUA。

不加“默认安装／自定义安装”的解释或重复选项；地址栏就是当前选择。目录不可写、空间不足、旧程序仍在运行等信息只在出现时展示。必要的许可告知不能因为文案精简而省略，但不额外添加教学页。创建桌面快捷方式若提供则作为一项简短复选框；开机启动保持默认关闭。

安装器不放 API 配置页、不引导逐个理解模型。完成后允许直接启动桌宠，在线功能缺少配置时由原有对应页面提供“获取 API”入口。

## 本体与可选组件

安装路径确认之后、开始下载之前，最多增加一个紧凑的“安装内容”页。没有任何可交付的可选组件时直接跳过，不显示灰掉的占位项。

| 项目 | 选择规则 | 第一版交付状态 | 大型资源 |
| --- | --- | --- | --- |
| RinaDesk | 固定选中，不可取消；安装器内置 | 开发预览已能打包，仍需脱离源码运行改造 | 无模型下载 |
| RinaYaki | 可选，默认不选 | 只有版本化发行物、依赖许可和校验信息齐全后才显示 | 模型、语音资源按功能首次使用下载 |
| RinaTomo | 可选，默认不选 | 只有控制器、Python/NapCat 边界和升级策略验证后才显示 | NapCat/登录相关依赖不静默安装 |

选择行只显示组件名、下载量、安装后占用和勾选框；不写教程。修改选择后总下载量与磁盘占用即时更新。组件都安装到同一用户选定的 `OurDeskPet` 组目录，但各项目仍拥有独立版本、配置、数据和卸载身份。

可选组件使用版本化发布清单，不从仓库分支、README 或在线脚本安装。每个条目必须锁定组件版本、目标架构、HTTPS 发行地址、压缩包字节数、展开后字节数、SHA-256 和最低兼容协议；缺任一字段则不进入可选列表。下载到本次安装的临时目录，逐项校验后再解包；失败只回退本次尚未登记完成的组件，不删除已存在的其他项目或用户数据。

模型和大型媒体运行时不纳入主安装器默认选择。它们由所属组件在首次使用相应功能时单独展示来源、体积、目录和真实下载进度，并能独立取消、续传和清理。这样升级 Desk 不会重复下载模型，也不会把 Yaki/Tomo 的缓存归到 Desk 卸载所有权。

## 进度反馈契约

耗时阶段必须有进度显示，但只有真实可计量部分显示百分比，不能用定时器假装匀速增长。各阶段独立显示，切换时标题同时更新，不把多个不等耗时阶段拼成伪总百分比。

| 阶段 | 进度来源 | 没有可用总量时 |
| --- | --- | --- |
| 检查环境／旧版本 | 检查项与实际完成事件 | 不定进度条＋“检查环境…” |
| 下载运行环境 | 实际已下载字节／可靠总字节 | 显示已下载量及不定进度，不猜剩余时间 |
| 安装 WebView2 | 官方安装器可获得的事件与退出结果 | 不定进度＋“安装运行环境…”；不能把下载完成当安装完成 |
| 安装 Desk | 实际解包／复制进度 | 使用 NSIS 可报告的安装进度；不宣称等于剩余时间 |
| 创建入口／完成登记 | 实际操作完成结果 | “正在完成…”；所有必要步骤成功才转完成页 |
| 开发侧构建 | 测试／前端／Rust／打包的阶段和工具输出 | 无可靠百分比的链接或编译步骤用活动指示及耗时，不显示虚假精确百分比 |

WebView2 已满足要求时跳过下载与安装。其外部安装进程若不提供细粒度进度，允许活动条，这是明确的忙碌状态而非停在 99%。不强制重启电脑；若依赖要求重启，单独显示真实结果，不提前声明应用可用。

## 状态与失败处理

首次安装：待安装 → 检查 → 必要时下载／安装运行环境 → 安装程序 → 登记入口 → 完成。任何失败进入可重试错误页；不创建看似可用却缺依赖的完成状态。

启动安装器时先做产品身份检测，不能只看目标目录是否存在。判定依据是本产品卸载登记、固定应用标识、已安装版本、主程序／卸载器和组件收据；目录中恰好有同名文件不算已安装。开发侧可用 `scripts/Get-InstallerPreviewState.ps1` 查看 `absent`、`installed`、`broken-installation`、`files-only`、`broken-or-foreign` 或重复登记；正式模板已覆盖首次安装、同版本修复、旧版本更新、禁止降级和登记残缺修复。

| 检测结果 | 默认操作 | 可选操作 |
| --- | --- | --- |
| 未安装 | 安装 | 取消 |
| 同版本且完整 | 取消／启动 | 修复；只补缺失或校验失败的程序文件 |
| 旧版本且完整 | 更新 | 取消；保留设置、授权、对话与自定义美术 |
| 新版本 | 取消并提示版本 | 开发模式才允许显式降级 |
| 登记存在但文件缺失 | 修复 | 取消 |
| 只有文件或目录身份不明 | 停止覆盖 | 选择新目录；由用户先处理原目录 |

可选组件各自维护小型收据，至少记录组件 ID、版本、架构、SHA-256 和受管文件。版本与哈希都匹配时直接复用本机文件、不下载；缺失或校验失败时只下载对应组件。下载先进入临时文件，校验成功后原子替换。这套检测同时作为后续更新器的基础，避免升级时重复下载完整组件。

“覆盖”不作为模糊按钮。普通更新和修复绝不删除用户数据；真正回到默认状态的动作明确命名为“彻底重置后重新安装”，放在次级入口并二次确认，逐项列出将清除的 Desk 设置、API 授权、对话和自定义美术。默认不勾选对话与自定义美术，也不触碰 Yaki／Tomo；只有用户明确选择的数据范围才进入清除清单。

升级：检测已安装版本 → 保存会话／正常退出 → 检查兼容性 → 更新程序文件 → 完成。关闭程序需走正常退出，不默认强杀。失败先保留数据与恢复记录，支持重新运行安装器修复；只有数据格式兼容且经过验证才恢复旧程序，不承诺 NSIS 自带完整事务回滚。

取消：开始写入前直接退出；下载中停止下载并清理本次临时文件；不可中断的替换步骤先完成安全收尾再响应取消。关闭窗口与取消按钮走同一逻辑，不能遗留无主子进程。已安装的共享运行环境不在取消／卸载时擅自删除。

常规开发安装可使用默认 `%LOCALAPPDATA%/RinaDesk Agent`，并由 `scripts/Remove-InstallerPreview.ps1` 做严格守卫清理。自动截图验收使用工作区顶层唯一的 `.rinadesk-installer-review`，通过 NSIS `/D` 参数真实安装，随后调用其卸载器；目录、登记、进程和快捷方式全部消失才算通过。`scripts/Build-InstallerPreview.ps1` 复用项目内 `.build-cache/cargo-target`，完成后把唯一预览及 SHA-256 覆盖到工作区顶层；产物不提交 Git。

卸载：关闭受管 Desk → 按程序所有权清单移除文件、快捷方式和启动项 → 保留用户数据。不能对整个安装根递归删除。彻底清除个人数据是独立显式操作，不默认勾选，不牵连 Yaki/Tomo 数据。

## 路径与旧版兼容前置项

1. 拆开源码根、安装根、资源根、用户数据根。当前 `runtime_paths.rs` 用 `app/src-tauri/tauri.conf.json` 验证项目根，`Build-Local.ps1` 仍是 `--no-bundle` 的开发安装路径；正式包不能依赖它们假装完整源码存在。
2. 保持对话默认 `<安装的 RinaDesk>/Conversations`，用户自选路径保持原样。安装目录必须可写；不默默切换到另一个保存位置。程序资源与用户生成文件分清所有权，升级／卸载不删对话。
3. 配置、余额授权、自定义美术的用户数据区要有稳定身份；现有源码版 `.env`、启动定位和已存数据的接入需明确确认，不能安装时自动扫描／合并其他源码副本。不能把加密授权导出成明文备份。
4. 原生系统默认用户目录不能被硬编码为开发者盘符。选择已存在的源码目录时不直接覆盖；只接受安全的新目录或可验证的本产品安装目录。
5. 运行时提示与产品指南使用打包资源／已有编译后备；源码阅读在未显式接入源码时不可用，不让安装版搜索用户磁盘寻找仓库。

## API 入口核验（2026-10-23）

测试使用当前源码、独立浏览器上下文及模拟 Tauri 调用；外网请求阻断，不读取、清除或保存真实密钥，不调用付费模型。它核验渲染与发出的跳转 URL，不等于登录网站成功或已安装 EXE 已更新。

| 位置 | 当前源码行为 | 核验 |
| --- | --- | --- |
| Desk Chat 侧栏／设置账户用量 | 无可识别账户时隐藏余额和今日花费，显示“获取 API”→ DeepSeek | 模拟界面通过 |
| Desk API 配置 | Chat / Tomo 分区保留 DeepSeek 获取入口，已有配置也可见 | 模拟界面通过 |
| Desk 内 Yaki 设置 | 百炼获取入口，已有配置也可见 | 实际组件＋模拟接口通过 |
| Desk 内 Tomo 大模型服务 | 控制器可用时显示 DeepSeek 获取入口 | 实际组件＋模拟接口通过 |
| 读取账户失败／打开平台失败 | 显示失败及相应反馈，不将读取失败误当未配置 | 模拟界面通过 |
| 有百炼 API 但无账务授权 | 保留账户栏并显示余额未连接；获取 API 不代替 RAM 授权 | 模拟界面通过 |
| Yaki 独立原生设置 | 当前“?”仅说明获取方式，没有等价直接跳转 | 源码核对；待对齐 |
| Tomo 独立原生设置 | 尚未找到等价 API 获取跳转入口 | 源码核对；待对齐 |

注意：共享余额卡根据三个项目汇总后的“支持平台＋非空 Key”账户集合决定空态，不等于当前 Chat 已配置或凭据验证成功。其他扩展已有账户时，Chat 没有 Key 也可能仍显示该账户；不支持余额识别的自定义平台也可能落入空态。发行前应复核这些状态表达，不能把“获取 API”按钮的有无当作全局连接诊断。

当前跳转目标由 `GetApiButton.tsx` 定义，平台页面最终登录与地域权限未在本次模拟测试中验证。原生入口缺口记录为发行准备项，本轮不擅自修改 Yaki/Tomo 的既有未提交实现。

## 实施顺序与验收门槛

当前源码打包、双语／协议占位、基础安装状态和脚本截图已完成 → 用户审核八张页面并决定视觉改造 → 处理正式协议、无源码运行及数据定位 → 接入版本化组件清单 → 干净 Windows 虚拟机验收 → 签名与发布审核。当前开发包只用于界面与构建链检查，不能发布。

验收包括：无 Rust/Node/源码、缺 WebView2、断网与下载失败、低空间、中文／空格路径、不同 DPI、已有数据升级、运行中取消、异常中断修复、卸载重装、单实例及开机启动保留。不因测试启动真实 API、登录 QQ 或移动用户媒体。
