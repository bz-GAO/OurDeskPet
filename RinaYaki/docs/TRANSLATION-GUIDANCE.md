# 按会话启用术语指导

## 使用

实时翻译 → 第2步「语言与显示」→「选择术语包…」→ 勾选 →「应用到本会话」。默认不选；当前窗口保留选择供继续开会话，但不保存成全局默认。全局设置的「通用」里提供「打开翻译指导文件夹」。

目录固定为 RinaYaki/translation_guidance/packs，每个包自带 pack.json。窗口内可刷新发现新包。语言方向不匹配的包无法勾选；已选包在切换到不匹配语言时不使用，切回后恢复。只显示原文时不加载术语、不调用翻译，配置也不向子进程传递术语包。

虹咲仍是草案：界面显示「草案试用」，勾选即明确允许本次试用；不会把文件中的 runtime_enabled 改成 true。取消所有勾选并应用即可关闭。待审文件、敬称构造示例永不加载。

## 本地检索边界

选中的包在独立实时进程启动时加载一次。仅本地扫描当前句子，不让模型阅读整个词典；无命中就不发 terms，有命中最多12对。较长名称优先，同一原文出现不同译法则跳过。全名可直接命中；简称/爱称需要本句或前两条已处理句出现同一人物全名。单字简称不注入。term.* 普通词要求近期存在同包专名作为语境；不代表进行了完整语义消歧。

例如直接说「ちぇみー」通常不注入；先说「田中ちえ美」，随后两句出现「ちぇみー」才发送「ちぇみー → 切咪」。这是有意保守的第一版，不把勾选虹咲本身视为所有昵称的人物证明。暂停/恢复不重新读取文件；文件修改应用于下一次新开会话。

原文不改写、不做 ASR 纠错、不自动套用「ちゃん→酱」。对英文进行词边界限制；姓名的空白/NFKC规范化不会改变字幕原文。

## 模型请求与核验

标准实时链路使用 Qwen-MT 的 `translation_options.terms`（source/target 对）和英文 `domains` 场景提示；不把规则混进 `messages` 的待翻译原文。启用的包可以提供英文 `domain_hint`，告诉模型题材和语气。LiveTranslate 使用 `session.translation.corpus.phrases`，仅传入无冲突、无需语境判断的固定译名；上下文别名不提前注入。官方接口说明：https://help.aliyun.com/zh/model-studio/machine-translation/ 和 https://help.aliyun.com/zh/model-studio/live-translator-client-events

session.json 记录包 ID、版本、内容摘要 hash 和是否草案试用；events.jsonl 的 notice/术语命中记录每句送出的术语对。stats.guidance_terms 是准备请求时选中的术语数量，不是模型采用率，也不保证请求成功。服务端最终是否完全遵守仍需实际试听验收。

术语不是保证正确性的强制后处理。未选包时标准翻译仍使用通用字幕场景提示；Lite 模型不接收 `domains`。失败时沿用原翻译错误显示，不静默重发无术语请求。离线视频翻译/精修尚未接入术语包。
